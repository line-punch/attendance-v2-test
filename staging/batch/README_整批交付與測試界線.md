## 3. 本輪修正的設計一致性

- 經人資核定的週六補班可以請假；未核定的週末仍阻擋。同日上班和休假互相衝突則拒絕。
- 連續請假上限嚴格 31 天，32 天拒絕。時段請假只允許同一上班日。
- 對外員工不可由前端自行指定身分、公司、HR 角色；人資待審核與核准必須限制同一公司，避免架構保留多公司時發生越權。
- 同一 requestId 改變內容或跨申請類型重用應拒絕。主管已核准後不能又被其他請求駁回。
- 遠端通知已送出但結果不明時，**先核對事件再重試**，不可直接重發；佇列策略已完成，真正 LINE 推播及永久儲存適配尚未接線。
- NFC 功能必須由伺服器驗證 NTAG 424 DNA 動態密文、讀取計數器防重播、時效與現場限制。**離線模型的布林值不能取代真正密碼學驗證**。
- 停班給薪不應冒充實際打卡；月結資訊只作就緒檢查，不計算真正薪資金額。

## 4. 要實際上 TEST001 前尚須建齊

1. **Google Apps Script 真正的安全適配器**：需先核對既有 TEST001 試算表表頭與審核狀態、現有部署版差異；在新的隔離後端只對 TEST001 員工與測試用 HR 身分開放，不可直接將本批 JavaScript 當成公開 endpoint。
2. **持久防重複與審核事務**：Google Sheets 不是資料庫交易，仍需 LockService、requestId、寫後讀回、失敗補償與原請求查詢；離線 TestStore 的 snapshot 回復功能不能直接代表 Google Sheets 原子交易。
3. **通知可靠性**：需確定可持久化的技術佇列位置、重送與已送證據；HR 工作日曆仍只新增既定兩張 HR 管理表，技術佇列不可偷偷變成另一套人資管理負擔。
4. **真正薪資／月結與本地備份**：需對照原 Excel、月結規則與已核准資料；目前只檢查資料已核對，沒有計算薪資、進行封存或備份。
5. **實體 NFC 424 DNA**：待標籤到貨後做 SUN 驗簽、複製網址、遠端代打、防重播測試，未驗證前關閉。
6. **訊息推播與四格正式銜接**：僅在全套 TEST001 離線規則和後端整合完成後，分 A–E 批次驗收，最後才討論正式系統的切換。所有按鈕需要執行中、完成與查詢原單的結果不明提示。
