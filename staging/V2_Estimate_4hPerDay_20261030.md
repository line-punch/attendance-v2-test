# LINE 打卡 V2｜每天 4 小時的剩餘工期估算（2026-10-30）

> 這是依目前 GitHub 隔離候選程式與既有實機成果所作的**工程量估算，不是保證完工日期**。每工作日按 4 小時有效開發／測試計。使用者希望整套先建齊，再一次分批驗收。

- TEST001 GPS 第 2 版的上下班打卡、綁定與 50 公尺限制已經獨立實機驗證。
- TEST001 固定虛構假單已在 iPhone LINE 經 V4 獨立唯讀服務成功讀回。V4 安全開關保持 disabled。
- 隔離 GitHub 有四格預覽、請假／補打卡、同公司人資審核、技術流水、通知 outbox 策略、月結準備度、NFC 安全入口及離線測試；不等於完成實際寫入、推播、薪資或上線。
- 本輪修補一項跨公司申請編號重複使用漏洞：即使兩家公司員工 ID 相同，也不能查回或重用另一公司既有申請。核心 34／34、技術流水 E2E 10／10 項模擬測試通過。**正式系統未修改**。

## 時間解讀與關鍵風險

- 若每天（含週末）都有 4 小時，18–26 工作日約為 3–4 週；若只在週一至五投入，約 4–6 週。
- 影響工期最大的是：多個 Google 帳號導致的正確專案／權限核對、既有正式／測試表頭差異、Apps Script 跨請求持久化、真正 LINE 通知、NFC 貼紙及設備是否到貨、薪資 Excel 的對接差異。
- 若未取得正確服務權限／NFC 標籤尚未到貨，**實際日曆時間會額外延後**，不能用增加離線測試數掩蓋。
- 任何不明寫入先核對原 requestId；不能重按或刪除測試資料。
- 不修改正式打卡與已通過的 TEST001 GPS 第 2 版；V4 繼續 disabled。
