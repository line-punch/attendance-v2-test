# V2 人資後台：公司工作日曆及天然災害出勤例外（隔離規格，2026-10-29）

> 只供 `line-punch/attendance-v2-test` 隔離開發、測試。**未建立、未變更正式 LINE 打卡 Google 試算表、Apps Script 或 Excel 薪資程式。** 本儲存庫為公開專案，不得放入員工姓名、個人 LINE ID、GPS、住址、私有金鑰或任何真實薪資紀錄。

## 1. 已確認原系統與不可改動的原則

- 員工每日只打兩次：**上班／下班**；**沒有午休打卡**。
- `打卡紀錄` A:K 是原始紀錄；`打卡紀錄_歷史` 欄位相同。不得以補卡或停班捏造／改寫原始打卡。
- `補打卡申請` A:M、`請假申請` A:L 保持原有欄位。
- LINE 原有四格維持「我要打卡、忘記打卡、我要請假、人資查詢」。員工端不增加「颱風假」打卡鈕或員工自行選擇的假別。
- 自動化只處理判定候選資料，不自動變更已核准假單、不自動調整薪資、不自動把未打卡判成曠職。
- 每月 5 日前為公司出勤結算時間；封存必須在結算、備份、異常核對後執行，與日曆判定分開開發。

## 2. 建議新增之**隔離資料表**（先規格，尚未實際新增分頁）

設計以「每月核定＋單日例外」代替全年每天手填；原始的上、下班打卡工作表完全不動。

### A. 工作日曆月份核定

| 欄位 | 內容 | 範例（全為虛構測試值） |
|---|---|---|
| A | 月份 YYYY-MM | 2026-11 |
| B | 公司 | TEST-詠晨 |
| C | 上班地點代碼 | TEST-新莊 |
| D | 狀態 APPROVED／DRAFT | APPROVED |
| E | 人資核定人 | TEST-HR |
| F | 核定時間 | 2026-10-29 09:00 |
| G | 核對依據／版本 | TEST-CALENDAR-2026 |
| H | 備註 | 測試 |

必須依 **公司＋實際上班地點＋月份** 各自核定；沒有核定資料、重複核定列、核定資料不完整，後端即不受理新的假單。

### B. 公司工作日曆

只記錄相對於「一般週一到週五上班、週六日休息」的**單日異動**，不需要每個工作日輸入一列。

| 欄位 | 內容 |
|---|---|
| A | 日期 YYYY-MM-DD |
| B | 公司 |
| C | 地點代碼（特定地點或 `*` 全公司） |
| D | 日別 WORK／OFF |
| E | 原因（國定假日、補班、公司休假等） |
| F | 官方或公司核定依據 |
| G | 狀態 APPROVED／DRAFT |
| H | 人資核定人 |
| I | 核定時間 |

同一天同範圍只能有一筆核定日別；**地點專用異動優先於全公司異動**。尚未核定的異動不能默默忽略，而是阻止假單繼續送出，待人資確認。

提醒：政府辦公日曆僅是參考來源，須依實際適用的勞動規則及公司排班核定後才生效。程式不自動宣稱任何日期為國定假日。

### C. 特殊出勤事件

| 欄位 | 內容 |
|---|---|
| A | 事件單號 |
| B | 事件日期 YYYY-MM-DD |
| C | 公司 |
| D | 地點代碼或 `*` |
| E | 類型，例如 TYPHOON／DISASTER |
| F | 停班起始時間（台灣時間） |
| G | 停班結束時間（台灣時間） |
| H | 官方公告或公司佐證 |
| I | 核定狀態 APPROVED／DRAFT |
| J | 人資核定人 |
| K | 核定時間 |
| L | 備註 |

**注意**：事件建檔僅記錄公告／公司事件，不代表該公司每個員工必然適用。

### D. 特殊出勤個別認定

| 欄位 | 內容 |
|---|---|
| A | 對應事件單號 |
| B | 員工 ID |
| C | 是否適用（TRUE／FALSE） |
| D | 經核定保護分鐘數 |
| E | 是否採公司照薪政策（TRUE／FALSE） |
| F | 核定狀態 APPROVED／DRAFT |
| G | 核定人 |
| H | 核定時間 |
| I | 說明（工作地、居住地／通勤必經地、協商等；**隱私資料不得公開**） |

員工是否適用，須根據其**工作所在地、居住地、通勤必經地**等實際情形由人資確認。與事件地點不同的人不應被全公司一鍵列入。若同日多事件重疊、資料待核定、個人適用結果缺漏，必須標註**待人資複核**。

## 3. 可重複測試的後端規則（純 JavaScript，不連真實資料）

測試檔案：

- `staging/AttendanceV2_CalendarAndEventService.js`：年月核定、單日工作日、假單跨週末／假日阻擋、天然災害事件與個別員工適用判定、出勤／薪資狀態候選。
- `staging/AttendanceV2_PayrollExceptionRules.js`：前一版「天然災害停班／實際工作／照薪」純判定邏輯。
- `staging/AttendanceV2_CalendarAndEventService.test.js`：隔離回歸測試。

**員工請假**：後端從已驗證的 LINE 身分綁定資料取得員工 ID、公司、所屬地點；不能相信前端自由傳來的員工 ID、公司、地點。由後端檢查起迄日期是否有非上班日、跨月日曆是否核定、有無已核定的天災停班事件與個人適用狀態。所有驗證通過後，才能進入「檢查既有假單／假別時數／新增請假／主管通知」階段。**此階段目前未串接、未開放寫入。**

**員工出勤／薪資**：正常上班日沒有打卡先標記缺卡待核對，不等於曠職；符合天災停班者由人資核定後，保留實際打卡與實際工作分鐘，另計算「受保護未出勤分鐘」及「公司照給薪資分鐘」。如果原本應上班 480 分鐘且整日停班、完全沒工作，則實際工作 0、停班照薪 480、曠職 0、全勤不得因停班而扣。若員工仍出勤、僅部分時段停班、或已核准特休重疊，須人資再核對，不自動加班或覆蓋假單。**部分停班的非停班時段仍未核定，不能將整天標示為全勤已確認；但保護時段不得被記為曠職。**

**技術限制**：尚未接入排班、薪資核定、假別餘額及權限資料。測試回傳都是候選結果，不能直接寫入正式 Excel 當月薪資表或年度出缺勤表。之後接正式後端時必須加鎖、防重複請求、審計記錄、權限驗證、書面核定後再開放。
