- 更換本預覽頁不會修改正式倉庫 `line-punch/line-punch`、正式後端、正式 Google Sheet 或原有 `attendance-v2-test/main/index.html` GPS 測試頁。

## 正式 LINE 四格選單的目標規格

目前正式 LINE 圖文選單仍維持四格，預計第四格「出勤紀錄」改名「人資查詢」，但目前未修改 LINE OA。

| 四格入口 | 對應介面 | 後端未來資料來源 |
| --- | --- | --- |
| 我要打卡 | 上班、下班；**當月**每個日期一列，原始時間精確到秒；空缺不以核准補卡時間補上 | `打卡紀錄` A:K |
| 忘記打卡 | 目前只可補今天/昨天，補上班或下班；顯示補卡日期、類型、補登時間、審核狀態 | `補打卡申請` A:M |
| 人資查詢 | **只讀**，當月與前兩個月：出勤、請假、補卡、本人基本資料 | `打卡紀錄` + `補打卡申請` + `請假申請` + `員工資料` |
| 我要請假 | 單日、連續多日、指定時段；保留事／病／特休／公／婚／喪及申請狀態 | `請假申請` A:L |

重點：
- 原本打卡只有「上班」「下班」兩類；**沒有午休開始或午休結束**。
- 查詢日期跨月/跨年時，月份選單只列本月及前兩個月。
- 跨週末、法定假日與補班日，必須由正式後端套用公司工作日曆計算，不依預覽中的曆日推算請假時數。
- 仍待設計與測試：權限驗證、雙重提交保護、主管審核、防重複寫入、出勤封存、NFC NTAG 424 DNA AES/SUN/SDM、iPhone/Android 對接。
- 歷史封存表 `打卡紀錄_歷史` A:K 與現行 `打卡紀錄` 相同；目前正式 Apps Script 沒有自動封存程式/觸發條件。先測試、核對備份，再考慮每月結算後封存。
- 主管通知與審核結果通知維持原需求，但網頁打卡成功提示不需 LINE Push。

## 新增規格：天然災害停班／計薪例外（2026-10-28）

此項規格由公司管理／人資薪資流程負責；**員工日常打卡四格不因天災停班增加任何打卡或請假操作**。以下僅記錄需求，尚未建立欄位、程式或觸發條件；不修改正式資料。

### 目的與原則

- 原本正常工作日，若有適用的政府天然災害停止上班公告（颱風、洪水、地震等），或經公司依適用規定認定之停班／無法出勤，不得因當日沒有打卡就自動記曠職、遲到、早退、事假、病假或扣全勤。
- 以「天然災害停班」或「天災出勤例外」作為**特殊出勤認定**，不是新增員工請假假別，更不是自動虛構上班與下班打卡時間。
- **公司希望採用當日照常給薪的政策**：對確認適用而未出勤的正常工作日，計薪不扣該日薪資；實際工作時數仍為 0；應計薪時數與實際工作時數必須分欄，避免影響加班計算。
- 台灣勞動部《天然災害發生事業單位勞工出勤管理及工資給付要點》（114/9/19 修正）第六點：符合工作所在地、居住地、正常通勤必經地停班公告等情形者，不得視為曠工/遲到、強迫補班或強制改請事假/特休、扣全勤或施不利處分；第七點為「宜不扣發工資」。政策上公司選擇照給，不能誤寫成所有情況法定必須給薪。
- 同一天仍有部分人員實際出勤時，保留真實打卡與實際工時；補償/額外給付依當日性質（正常工作日、休息日、例假、國定假日）及法令與公司政策另外計算，不一律當加班或自動雙倍。
- 原本已排定的特休/其他假單與天災停班重疊時，應交 HR 依約定及個案協商複核；**不能默默改掉已核准假單**。

### 預計資料模型與計算優先順序

- 建議共用「公司工作日曆」＋獨立「特殊出勤事件／例外認定」資料：日期/時段、事件類型、適用公司/工作地點/員工、停班公告依據與連結、適用條件、是否照薪、建立與審核紀錄。
- 不可只依公司地址一鍵將全部員工判定停班。不同工作地（如新莊、楊梅）、居住地、通勤必經地可能不同，允許特定人員適用。
- 計薪匯入時優先比對核准的例外事件，再處理「未打卡」缺勤判斷：若已核定天災停班，打卡空白可視為合規，曠職=0、假別扣除=0、全勤不扣；應計薪依公司照給政策處理。
- 出勤統計/年度紀錄保留「實際打卡/實際工時」與「停班給薪」的區別，薪資表可獨立標示有薪停班時數。
- 若是正常請假申請跨到公司確認的「非上班日」，沿用先前約定：禁止送出跨越非上班日的假單，提示拆單；避免與已經存在的假單自動沖突。

### 實作與驗證限制

1. 先規劃工作日曆與例外資料，不動正式 Google Sheet / Excel 巨集。
2. 在隔離測試資料中驗證整日停班、部分停班、不同工作地、員工居住地單獨停班、停班當日仍出勤、已有特休申請與月薪匯入；工資計算結果需人工確認。
3. 測試通過再考慮與現有年度出缺勤紀錄表、當月薪資表匯入流程銜接。
4. 不要依新聞日期自動替全部員工建立停班，也不自動改動正式歷史紀錄，應以適用的官方公告及 HR 核定為依據。

## 2026-10-28 本次新增：請假跨非上班日即時阻擋（預覽）與天災計薪模型

### 請假頁面（安全預覽）

- 在日期上方顯示：「請以實際上班日選擇請假日期；期間遇週休、國定假日或公司休假日請拆分假單。」
- 日期範圍若跨一般週六／週日，列出哪些日期不能請假，並將「預覽送出請假」設為 disabled。
- 指定時段請假限單一上班日，缺少起迄時分或時間倒置也阻擋；沒有選假別或填原因時同樣不能送出。
- 新增純計算模組 \`employee-center-preview/workday-rules.js\`：預設平日上班、週六日非上班；**可依已核准公司工作日曆以 \`overrides\` 覆寫**國定休假、補班週六、特定休假日。
- 正式後端必須先核對工作日曆 \`verifiedMonths\`，若月曆未經核准，回傳 \`CALENDAR_UNVERIFIED\` 拒絕請假送出。僅前端阻擋不夠，後端須再次驗證。
- **重要限制**：目前預覽未連接公司完整年度日曆，頁面即時檢查僅展示週末規則；不能把週一至週五的「預覽有效」理解成已排除國定假日。預覽不會真的送出申請。

### 天然災害停班與薪資出勤例外（純邏輯，非正式整合）

- 開發分支：\`feature/workday-leave-typhoon-rule-20261028\`
- 測試模型：\`staging/AttendanceV2_PayrollExceptionRules.js\`
- 可重跑測試：\`staging/AttendanceV2_WorkdayAndPayroll.test.js\`（15／15 驗證通過）。
- HR 人工確認「適用員工／日期／工作地點／停班時段」後，才記天災出勤例外。不是自動對全公司記休假或自動更改打卡／假單。
- 公司選擇天災符合規範當日**薪資照給**；若原排定工作 480 分鐘且完全停班、未出勤，\`actualWorkedMinutes=0\`，\`paidStopMinutes=480\`，曠職不計且不影響全勤。
- 部分停班、實際仍有工作、與已核准請假重疊時，標記「人資複核」，不自動補假、扣假、改薪或計算雙倍工資。
- **尚未**與 Google Sheets、LINE 正式打卡及 Excel 薪資系統串接，不會修改真實員工紀錄。

### 已檢查的案例

- 星期五到下週一：跨週六、週日而阻擋；兩張假單分別申請。
- 補班週六（經日曆覆寫）：允許；平日公司休假／國定假日（經日曆覆寫）：阻擋。
- 日期格式錯誤、起迄顛倒、日曆未核准：阻擋。
- 天災全日照薪但實際工作 0、僅部分停班、實際有上班、非適用員工、核准請假重疊等不錯列曠職。
